Audit a precursor claim

A p-value cannot tell a real association from an artefact, because several very different mechanisms produce the same p. What separates them is how the result responds when the analysis is perturbed. This tool applies fifteen such perturbations, and reads the pattern of responses against reference scales measured on a real study.

Your data

Two columns, one row per day, in time order: the candidate predictor, then 1 on days an event occurred and 0 otherwise. Commas, tabs or spaces. A header line is ignored. Nothing leaves your browser.

The seven explanations it weighs

A p-value cannot tell these apart, because most of them produce small ones. What separates them is how the result behaves when the analysis is perturbed, and each leaves a different signature across the battery. The animation above cycles through those signatures as they were measured on the training set.

What it is doing

Each mechanism leaves a different signature across the battery. A real association barely moves when the validation split changes and survives thinning of clustered days. A calendar leak collapses under a chronological split, and its predictor reconstructs the date almost exactly. Aftershock clustering collapses when repeated days are thinned. A lookahead window collapses when sampling is made strictly causal. A search artefact collapses under a correction for everything that was tried.

The reference scales come from measurement rather than assumption. In the study this was built for, the validation split moved a real seismicity signal by 0.008 AUC and a calendar-driven forcing bank by 0.208; declustering moved a tidal harmonic from p = 0.015 to p = 0.596; making a GRACE window causal moved it from p = 0.0000 to p = 0.36.

Why the answer is a set, not a verdict

The classifier is wrapped in conformal prediction, so its output is the set of explanations consistent with the fingerprint at a stated confidence. An ambiguous claim produces a large set and says so, instead of a point verdict that hides the ambiguity. Coverage is calibrated per class on held-out data and was verified over sixty repeated splits:

The levels are deliberately unequal. A real association is held to 99% coverage and every artefact to 90%, which makes the tool reluctant to rule out a real effect and comparatively willing to name an artefact. An auditor should be able to refute much more confidently than it can endorse.

What it cannot do

It names an artefact confidently in about 60% of cases where one is genuinely present, and falsely accuses a real association in 4 cases in 1000. The remaining cases return an ambiguous set, which is informative in itself: a set of real and clustering tells you precisely which check to run next.

It is trained on mechanisms planted into a real catalogue, so it recognises the artefacts it was shown and not ones nobody has thought of. A fingerprint far from anything in training gets no verdict at all rather than a confident guess. And a clean result is never evidence that a claim is true; it is only the absence of the specific defects tested here.

How the model gets into your browser

The classifier is a gradient-boosted ensemble of 1400 trees trained in Python and exported node by node. Two checks guard the port. The exported ensemble is re-evaluated with an independent implementation and compared against scikit-learn, which agrees to 0 exactly. And the fifteen fingerprint axes, reimplemented here, are compared against the Python originals on test series, agreeing to 2.7 × 10⁻¹¹ in the worst case. Both checks fail the build rather than shipping a silent disagreement.
